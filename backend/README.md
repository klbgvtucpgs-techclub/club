# VTU Clubs Backend (FastAPI + Supabase)

FastAPI + SQLAlchemy on a **Supabase Postgres** database, with **Supabase Storage** for gallery photos.
It implements the plan: student registration with email OTP, backend-generated club IDs, gallery, announcements,
registration links and a secured admin API.

> Status: the code compiles and ships with a pytest suite, but it was written without network access, so the
> dependencies were never installed and the tests were never run. Run `pytest` first (step 6) and fix anything it finds.

Requires Python 3.9 or newer (3.11+ recommended).

## 1. Set up Supabase
1. Create a project at supabase.com. Save the database password.
2. **Database URL:** Project Settings > Database > Connection string. Use the **Session pooler** string (port 5432).
   Put it in `DATABASE_URL`. URL-encode special characters in the password (`@` becomes `%40`).
3. **Storage:** Storage > New bucket named `club-photos`, set **Public** (photos are public gallery images).
4. **Keys:** Project Settings > API. Copy the Project URL into `SUPABASE_URL` and the **service_role** key into
   `SUPABASE_SERVICE_KEY`. The service key bypasses all security. Keep it server-side only, never in frontend code or Git.

## 2. Install and configure
```bash
cd vtu-clubs-backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # Windows: copy .env.example .env  (then edit it)
python -c "import secrets;print(secrets.token_urlsafe(48))"   # paste into SECRET_KEY
```

## 3. Create the tables, clubs and first admin
```bash
alembic upgrade head                 # 0001 creates tables, 0002 enables Row Level Security on Supabase
python -m app.scripts.seed           # inserts the 4 clubs (TECH, SPORTS, CULT, MM prefixes)
python -m app.scripts.create_admin yourname --super   # prompts for a password
```
Row Level Security is on for every table with no policies, so the public Supabase REST API cannot read your data.
This backend connects as the table owner and is unaffected.

## 4. Run
```bash
uvicorn app.main:app --reload
```
API docs: http://127.0.0.1:8000/docs. With `EMAIL_BACKEND=console` OTP emails are printed in the terminal.
No Supabase yet? Set `DATABASE_URL=sqlite:///./dev.db`. Photos then go to `uploads/`.

## 5. Connect the frontend
Copy `api-client/api.js` into your frontend and import its functions. Set `FRONTEND_ORIGINS` to your site's origin.
Frontend and API on different sites (for example vercel.app and onrender.com) need `COOKIE_SAMESITE=none` and
`COOKIE_SECURE=true` (HTTPS). Hosting both under one parent domain (`www.` and `api.`) is simpler and safer.

## 6. Test
```bash
pytest
```

## Endpoints
| Method | Path | Notes |
|---|---|---|
| GET | `/api/clubs`, `/api/clubs/{slug}` | public |
| GET | `/api/registration-links/{token}` | check a shared link and its club |
| POST | `/api/auth/register` | validates the form, returns `pending_id` (nothing is saved as a member yet) |
| POST | `/api/auth/send-otp` | `{purpose:"register", pending_id}` or `{purpose:"login", email}` |
| POST | `/api/auth/verify-otp` | OTP + captcha, then creates the student and club ID and sends the confirmation email |
| POST | `/api/auth/login`, `/logout`; GET `/me` | passwordless student login by email OTP |
| GET | `/api/memberships/me` | the student's club IDs |
| GET | `/api/announcements?club=slug` | published only (club-specific plus global) |
| GET | `/api/gallery?club=&event=&page=&page_size=`, `/api/gallery/albums` | public |
| POST | `/api/admin/login`, `/logout`; GET `/me` | admin session; `login` and `me` return `csrf_token` |
| GET | `/api/admin/dashboard` | totals, members per club, recent registrations |
| POST / DELETE | `/api/admin/photos`, `/photos/{id}` | multipart upload (`club_slug,title,event_name,file`) |
| GET / POST / PATCH / DELETE | `/api/admin/announcements[/{id}]` | drafts, publish, unpublish, club targeting |
| GET / POST / PATCH | `/api/admin/registration-links[/{id}]` | public token, start and expiry dates, enable or disable |
| GET | `/api/admin/students?q=&club=&page=` | search by USN, name, branch or club ID |
| GET | `/api/admin/students/export` | CSV (formula-injection safe), audited |
| PATCH | `/api/admin/memberships/{id}` | `active`, `pending` or `suspended` |
| POST / GET | `/api/admin/admins`, `/audit-logs` | superadmin only |

## How the plan's rules are met
- **Club ID is generated by the backend**, as `TECH-<joining year>-0001`. `club_counters` is locked with `SELECT ... FOR UPDATE`,
  so concurrent registrations never get the same number. `membership_code` and `(student, club)` also have unique constraints.
- **USN and email are unique.** A student can join several clubs and gets one ID per club.
- **OTP:** 6 digits, stored only as an HMAC hash, 5 minute expiry, 3 attempts, 60 second resend cooldown, single use.
  Captcha (Turnstile, hCaptcha or reCAPTCHA) is checked on `verify-otp`. It is skipped while `CAPTCHA_SECRET` is empty.
- **Admin security:** bcrypt hashes, HttpOnly cookie sent only to `/api/admin/*`, CSRF token header on every write,
  server-side role checks on every admin route, login rate limit, audit log of sensitive actions, upload validation
  (size, real image decoding, allowed formats, random file names).
- **Not just an email check:** OTP proves access to an email, not VTU enrolment. Use `ALLOWED_EMAIL_DOMAINS`,
  `REQUIRE_REGISTRATION_LINK=true` and `REQUIRE_ADMIN_APPROVAL=true` to restrict membership.

## Deploy (Render, Railway, Fly.io or Docker)
Set the same variables as `.env` in the host's dashboard with `APP_ENV=production`, `COOKIE_SECURE=true`,
`EMAIL_BACKEND=smtp` and `TRUST_PROXY=true`. Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
Run `alembic upgrade head` once on deploy. In production the app refuses to start with a weak `SECRET_KEY`,
a non-SMTP email backend or insecure cookies, and the `/docs` pages are turned off.

## Known limits
- The rate limiter is in memory. With several server instances, use a shared limiter such as Redis.
- Students log in by email OTP only, with no passwords, as the plan's form has no password field.
- The old frontend demo kept data in the browser. The pages must be switched to call this API through `api.js`.
